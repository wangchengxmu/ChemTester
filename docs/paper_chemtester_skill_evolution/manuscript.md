# From Open Textbooks to Audited, Error-Driven Skills for Chemistry Language Models

## Abstract

Large language models can answer many chemistry questions directly, but their reliability degrades when a problem requires exact constants, multi-stage bookkeeping, specialized experimental knowledge, or disciplined use of external tools. We developed an auditable chemistry support system that converts heterogeneous textbook-derived notes into a compact set of model-facing problem-solving skills and then refines those skills through error-driven evaluation. The retained source layer contains 92 ingestion records assembled before the main ChemTester evaluation campaign. These records describe extraction, overlap assessment, replacement searches, and blocked sources rather than a uniform page-by-page reading log. The initial project snapshot organized this material into a concept-based hierarchy containing 738 principle files and 223 executable-tool files. A compact registry subsequently separated the small set of instructions presented to the model from the much larger supporting memory. Before retrospective refinement, an immutable manifest froze a ten-capability compact baseline and prohibited use of a sealed 400-question acceptance set for development. A retrospective run then reduced 7,381 archival benchmark items to 3,086 canonical question families, evaluated each family with GPT-5.6-sol at xhigh reasoning, and allowed promotion only after a failed item was diagnosed, repaired, rerun cleanly, and recorded with evidence. The current registry contains 71 active and 7 retired capabilities supported by 104 active evidence records. On the sealed acceptance set, the current GPT configuration obtained 368/400 (92.0%), compared with 358/400 (89.5%) for a historical legacy-support composite, although runtime differences prevent a causal skill-only interpretation. A controlled GLM-5.3-flash comparison produced 346/400 with skills and 344/400 without skills (McNemar p = 0.871), showing no statistically persuasive aggregate benefit in that model. Finally, a live audit of Chemistry LibreTexts on 4 September 2026 found 139 immediate shelf entries, corresponding to 129 canonical named works after excluding six generic supplemental-module containers and collapsing four title aliases. Only 42 canonical works had an exact title or book-root trace in the repository; 87 require manual provenance adjudication. The system therefore demonstrates a practical route from broad chemical reading to evidence-backed procedural memory, while also showing why source coverage, licensing, and controlled ablation must remain first-class parts of any claim about learned scientific skills.

## Introduction

Chemistry questions combine several forms of difficulty. A model may need to recognize a familiar reaction class, derive a numerical result, distinguish thermodynamic possibility from kinetic observability, interpret a spectrum or image, or retrieve a value from a trusted table. A single static prompt is poorly suited to all of these cases. It is either too short to contain the required specialist knowledge or too large to present the relevant material without distracting the model. Retrieval-augmented generation addresses part of this problem by retrieving external passages, while tool-using systems interleave reasoning with actions and self-refinement systems improve an initial response through feedback [1-4]. Chemistry benchmarks such as MMLU chemistry, GPQA, and ChemBench expose the breadth and precision required for a scientifically useful implementation [5-7].

The ChemTester project approaches this problem as a memory-engineering and evaluation problem rather than as model-weight training. Textbook and reference material is converted into a layered external memory. A compact skill index tells the model when to use a principle, lookup resource, or executable tool. Benchmark failures can propose additions to that compact layer, but they cannot directly edit it. Promotion requires a clean rerun, structured evidence, and integrity checks. This arrangement aims to retain three properties that are often lost in informal prompt refinement: traceability from a capability to its supporting evidence, separation between development and acceptance data, and reversibility when capabilities overlap or prove too narrow.

This paper reconstructs the complete retained lineage of the system. We begin with the source-ingestion files associated with the earlier OpenClaw workflow, describe their conversion into concept-oriented memory and executable tools, and trace the later evolution of the compact skill registry. We then report retrospective and acceptance-set results with explicit limits on causal interpretation. Because the intended source scope was the online chemistry library rather than a fixed hand-selected list, we also audit the current Chemistry LibreTexts catalog and compare it with repository evidence. This final analysis changes the appropriate claim: the project drew broadly from the library, but the retained records do not support the statement that every current book was completely read.

## Results

### A heterogeneous reading corpus became a concept-based chemistry memory

The retained source corpus is not a conventional bibliography. It consists of 92 files in `chem-memory/sources/ingestion`: 86 Markdown records and six structured JSON records. Individual records document activities such as chapter mapping, pass-based extraction, source replacement, overlap analysis, and access failure. Four records explicitly identify an "OpenClaw Scout" as the source agent. The remaining records do not carry a consistent agent identifier, so the repository supports an OpenClaw origin for part of the early workflow but not for every ingestion file.

The records also show that "read" was not a binary operation. Some files report a completed first-pass scan and enumerate chapters and new concepts. Others extract only topics judged absent from the existing memory. The Oxtoby materials-science assessment, for example, records more than 85% overlap and explicitly skips three groups of descriptive topics. The Skoog instrumental-analysis record is marked blocked because the source page was an empty under-construction placeholder. A Petrucci record documents a failed URL and recommends replacement sources, but discovery of those replacements is not itself evidence that each replacement book was subsequently processed. These distinctions are essential for reconstructing coverage.

The material was normalized into a layered memory whose unit of organization is the chemical concept rather than the source chapter. The repository defines an always-loaded ontology/router (L1), detailed principle and decision files (L2), executable functions and tools (L3), lookup references and practical routines (L4), and worked examples or records (L5). The prescribed path is L1 to L2 to L3, with L4 and L5 used for exact data and validation. At the initial local project snapshot on 11 April 2026, the memory contained 738 L2 files and 223 L3 files. The current tree contains 847 L2 files and 226 L3 files, excluding bytecode caches. This growth reflects both source-derived content and later benchmark-driven additions.

The architectural choice matters. Chapter-oriented storage preserves provenance, but it is a poor retrieval key for a problem whose decisive operation may be "bind each temperature to its role" or "separate equilibrium potential from kinetic onset." The concept layer therefore converts source material into reusable decision procedures. Detailed formulas and resources remain available, while a compact model-facing layer can stay small enough to be selected reliably.

### A compact registry separated model-facing instructions from the full memory

The compact skill is represented in both Markdown and a structured registry. Each active registry entry contains a stable capability identifier, a title, retrieval terms, a use condition, ordered steps, optional resources, guard conditions, timestamps, and evidence records. Retirement records preserve the displaced entry and explain replacement or consolidation. This structure allows the project to merge narrow capabilities into broader ones without deleting their provenance.

An immutable snapshot created on 27 July 2026 froze the pre-retrospective state. Its manifest contains hashes for the compact skill, registry, selected supporting L2 files, the L3 function registry, runtime policy, and configuration. It also states that the sealed 400-question acceptance suite must not be executed, altered, or used for skill development. The baseline registry contained ten active and two retired capabilities. Nine of the active baseline capabilities remain active in the current registry; one hydroxide-buffer precipitation capability was later consolidated into a broader coupled solubility and acid-base procedure.

The current registry, updated on 31 August 2026, contains 71 active and seven retired capabilities. The active entries span equilibrium and speciation, thermodynamics, spectroscopy, organic mechanism and stereochemistry, inorganic structure, analytical measurement, hazards, and answer-representation controls. Their scope is procedural. For example, the registry does not merely store a statement about real gases; it instructs the model to select a compressibility representation appropriate to the supplied state variables and to keep virial orders dimensionally consistent. Likewise, spectroscopy entries specify how to identify the information channel before interpreting a signal. These are intended to transfer across numerical values and surface forms.

### Retrospective failures were converted into evidence-backed capabilities

The retrospective workflow processed historical questions from published open benchmarks while excluding textbook questions, generated questions, and the protected acceptance suite. The original archival pool contained 7,381 items. Exact and semantic deduplication reduced this pool to 3,086 canonical question families, eliminating 4,295 duplicate items in 1,876 groups. The semantic audit used `sentence-transformers/all-MiniLM-L6-v2`; 426 pairs were auto-approved and 20,066 borderline pairs were reviewed under the active family policy, producing 20,492 applied semantic pairs. Rewordings, parameter variants, target-species variants, and answer-format variants could therefore belong to one family rather than contribute repeated development evidence.

For each canonical family, the performer received the problem without the benchmark-recorded answer and with skill evolution disabled. An evaluator scored the frozen answer. When an answer was incorrect, a repair worker diagnosed the failure and proposed a transferable change. The worker could not alter the question, options, benchmark key, or frozen initial result, and it could not directly write the orchestrated compact skill or registry. Instead, the controller applied the proposed capability as an in-memory overlay and reran the same frozen item. Promotion required a correct clean rerun, no unresolved blockers, a redacted evidence record, and schema-valid registry content. A separate updater then merged or added the capability, rebuilt the compact index, and wrote a receipt containing hashes.

This process generated 105 promotion receipts and left 104 evidence records attached to currently active capabilities. The difference is expected because receipts include historical promotion and consolidation events, whereas the active evidence count describes the current registry. The completed retrospective status reports 2,854 correct-first-pass outcomes, 105 repaired outcomes, 272 source-issue outcomes, and 556 failed attempts as historical counters that may include pre-deduplication variants. Thirteen items were sent to human review. Source issues were kept distinct from model errors, and a missing reference resource was treated as a support warning rather than an automatic correctness failure.

The repair test establishes that a proposed instruction can correct the triggering item under controlled controller rules. It does not establish broad transfer because the same item is used to validate the repair. Transfer must instead be assessed on questions that were not used to create the skill. This limitation motivated the immutable acceptance suite and the later model comparisons.

### Evaluation separated observed performance from causal attribution

With GPT-5.6-sol at xhigh reasoning and the current compact skill, the sealed 400-question acceptance set yielded 368 correct answers (92.0%). A historical legacy-support composite yielded 358/400 (89.5%). Pairwise comparison found 352 questions correct in both conditions, 26 wrong in both, 16 correct only in the current run, and six correct only in the historical composite. The observed difference was ten questions, or 2.5 percentage points, with a two-sided exact McNemar p value of 0.0525. Older reference runs obtained 355/400 for the earlier tool-skill configuration and 359/400 for curated-v2 autonomous support.

These GPT results show that the current system produced the highest observed score among the available runs. They do not isolate the effect of the skill. The historical runs differ in support composition, runtime snapshots, and latency, and the 358/400 historical composite is not a controlled no-skill arm. On the 220-question externally published subset, the current run scored 193/220, compared with 194/220 for the historical composite and 193/220 for curated-v2. The aggregate gain therefore arose outside that subset and was concentrated in parameterized textbook-style and vision questions. A definitive GPT ablation still requires the same model/runtime snapshot, evaluator, question order, visual helper, and inference parameters, with only the compact skill switched on or off.

A controlled GLM-5.3-flash experiment provides a cleaner causal test for that model. The skill-enabled arm scored 346/400 (86.5%) and the disabled arm scored 344/400 (86.0%). Of the paired outcomes, 326 were correct in both arms, 36 were wrong in both, 20 favored the skill, and 18 favored no skill. The exact McNemar p value was 0.871. The skill-enabled arm was also slower, with median latency of 57.74 s compared with 7.87 s. Under these conditions, the compact skill did not provide a statistically persuasive aggregate accuracy improvement for GLM-5.3-flash and incurred substantial latency. The value of the framework therefore lies at present in auditability and targeted procedural support, not in a universal claim of model-independent accuracy improvement.

### The live online library is broader than the evidenced reading corpus

We audited the eight curated Chemistry LibreTexts shelves on 4 September 2026: Introductory, General, Organic, Inorganic, Analytical, Physical and Theoretical, Biological, and Environmental Chemistry [8]. The shelf API returned 139 immediate entries. Six entries were generic supplemental-module containers rather than named books. The remaining 133 rows reduced to 129 canonical named works after normalization of `Book:` and `Map:` prefixes, punctuation, and four duplicate or alias title groups.

We then searched the complete `chem-memory` tree for exact normalized titles and book-root paths. Forty-two canonical works had at least one exact trace; 87 had no exact title or root trace. This is an intentionally conservative screening test. It can miss a source when LibreTexts has renamed or moved a book. The current catalog entry "Analytical Chemistry 2.1 by David Harvey," for example, lacks an exact title match even though the repository contains clear Harvey-derived analytical-chemistry records under earlier paths and titles. Conversely, an exact trace proves only that a source is mentioned; it does not prove full reading or successful extraction.

The audit nevertheless answers the coverage question. The current repository does not contain evidence that all 129 canonical works were read. At least some works were explicitly skipped or blocked, and many current titles have no exact trace. A defensible completeness statement would require manual classification of every catalog row into fully extracted, partially or delta extracted, assessed and skipped, blocked, catalog-only, or untraced. The complete live catalog and screening result are supplied as machine-readable supplementary files.

## Discussion

This work contributes an engineering pattern for scientific model support. Broad reading is first converted into a structured external memory. A compact registry then exposes only reusable problem-solving procedures to the model. Finally, failures propose changes through a gated workflow that preserves the original answer, isolates source issues, validates the proposal, and records the promotion. The result is inspectable in a way that an accumulated system prompt or an undocumented set of retrieval notes is not.

The retrospective process also illustrates why deduplication is part of scientific validity rather than merely a storage optimization. If many parameter or wording variants from one question family are counted independently, a skill can appear repeatedly useful while correcting one narrow template. Collapsing 7,381 archival items to 3,086 families reduced this source of pseudo-replication. It does not eliminate all dependence between questions, but it aligns the unit of development more closely with the intended unit of transfer.

The evaluation results require restraint. The current GPT configuration improved by 2.5 percentage points over the historical composite and produced the strongest observed score, but the comparison is not a same-runtime skill ablation and narrowly misses the conventional 0.05 significance threshold. The controlled GLM comparison showed only a 0.5-point difference with nearly symmetric discordant pairs and a large latency penalty. These results are consistent with a system whose benefits are capability- and model-dependent. They do not support the claim that adding the current skill set will improve every model or every chemistry benchmark.

The source audit exposes a second limitation. The project was conceived against a broad online-library scope, but its retained provenance was optimized for extraction work rather than for proving complete library coverage. Titles changed, pages disappeared, some sources were evaluated only for overlap, and the consolidated book ledger remained incomplete. Future ingestion should assign a stable source identifier to every shelf entry, store retrieval timestamps and licenses, and record chapter-level states. The live catalog snapshot in this study provides a baseline for that repair.

Licensing is also source-specific. Chemistry LibreTexts aggregates materials under licenses that can differ by book, and source pages or external hosts may change their terms. The present study did not train model weights; it created an external memory and procedural registry. That distinction does not remove the need for a source-by-source review before redistributing extracted textbook content. The paper and catalog metadata can be shared independently of the source-derived memory, while release of the latter should remain conditional on license verification.

## Methods

### Historical artifact reconstruction

All counts were derived from repository files rather than recollection. The initial tree was measured at Git commit `1fa8e9fc244d94b16279a85f9f59ad66d0853f74` dated 11 April 2026. Current counts excluded `__pycache__` directories and `.pyc` files. Source-ingestion records were counted directly in `chem-memory/sources/ingestion`. Agent attribution was accepted only when stated in a retained record. The original external OpenClaw workspace was unavailable at the time of analysis, so the reconstruction is limited to artifacts copied into ChemTester.

### Source-state taxonomy

We defined six source states. `Extracted` denotes records that state that relevant content was processed into the memory. `Partial/delta` denotes selective extraction of material judged new relative to existing coverage. `Assessed/skipped` denotes a reviewed source for which extraction was intentionally omitted, usually because of overlap. `Blocked` denotes an inaccessible or empty source. `Catalog-only` denotes a source mentioned as an alternative or discovery without retained extraction evidence. `Untraced` denotes no exact current title or book-root match. These states describe evidence in the repository, not the intrinsic quality of a book.

### Live LibreTexts catalog audit

The audit script queried the immediate subpages of the eight curated Chemistry LibreTexts bookshelves through the MindTouch API. Each returned row retained shelf, title, path, page identifier, creation time, modification time, and API URI. Generic supplemental-module containers were excluded from the named-work count. Canonical keys were generated by removing leading `Book:` and `Map:` labels, lowercasing, replacing punctuation with spaces, and collapsing whitespace. Rows sharing a canonical key were treated as aliases for counting purposes. Exact repository traces were found by matching normalized titles or decoded book-root names against files under `chem-memory`. The audit produced CSV, JSON, and Markdown outputs and recorded a SHA-256 hash of the JSON snapshot.

### Layered memory and compact capability schema

The memory architecture consists of a router, concept instructions, executable tools, reference material, and examples. The compact registry is the controlled interface to that larger system. A capability entry requires a stable identifier, retrieval terms, an explicit use condition, ordered actions, resources when needed, and guard conditions that prevent common overgeneralizations. Evidence records link capabilities to redacted evaluation artifacts. Retired entries remain in the registry with reasons and replacements.

### Retrospective evaluation and promotion

The retrospective loop used GPT-5.6-sol with xhigh reasoning on canonical question families drawn from published historical open benchmarks. Textbook-derived, generated, and protected acceptance questions were excluded. Initial answers were frozen before evaluation. Incorrect items could trigger a repair proposal, but the repair worker was prevented from editing problem data, benchmark keys, initial answers, and orchestrated skill files. Proposals were tested as temporary overlays. Only a correct clean rerun without integrity or leakage blockers could be promoted. Ambiguous cases were deferred to human review rather than used to force a skill update.

### Acceptance evaluation and statistics

Acceptance results were read from aggregate comparison reports; individual sealed questions were not inspected for this study. Accuracy was calculated as correct items divided by 400. Paired changes were summarized as both-correct, both-wrong, skill-only, and comparator-only counts. Two-sided exact McNemar tests used the discordant pairs. Comparisons were designated controlled only when model, runtime snapshot, evaluator, helper tools, item set, and inference settings were held fixed except for skill availability.

## Limitations

The historical source corpus is incomplete as a reading ledger. Exact title matching has both false negatives and false positives. The OpenClaw attribution is explicit for only four retained records. Retrospective repair uses the triggering item for validation and therefore measures local correction, not transfer. Historical counters can include pre-deduplication variants. The GPT acceptance comparison is not a controlled skill ablation. The controlled GLM experiment covers one model and one configuration. Finally, the live online catalog is mutable; all coverage counts are tied to the 4 September 2026 snapshot.

## Data and code availability

The catalog audit script and its timestamped outputs are included with this manuscript. The compact skill registry, immutable pre-retrospective manifest, deduplication audits, promotion receipts, and aggregate evaluation reports remain in the ChemTester project. The sealed 400-question acceptance suite is intentionally excluded from analysis and release. Any public release of source-derived memory content requires a separate license audit for each source work.
